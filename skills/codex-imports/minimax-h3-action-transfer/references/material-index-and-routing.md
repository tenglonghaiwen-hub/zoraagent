# 素材索引与能力路由

## 每次任务都生成上传清单

根据实际存在并已检查的素材生成紧凑、连续、无空位的编号。先告诉用户每个编号应上传哪类素材，再在提示词中使用同一编号。索引使用简短用途标签，不写完整文件名、扩展名或本地路径；不要假设聊天附件顺序等于 H3 上传顺序。

默认分组顺序：

1. 人物身份图片：主脸/主身份优先，其次为补充全身或多视角。
2. 独立服装图片。
3. 场景图片，仅在用户确认场景替换、光线参考或色彩参考时纳入。
4. 新道具图片。
5. 其他被确认的风格、光线或关键帧图片。

省略不存在或未启用的分组，然后连续编号。例如只有一张人物四视图和一张场景图时：

- `图1`：人物四视图，锁定身份、五官、发型、体型和图中服装。
- `图2`：场景图，只负责环境；光源是否也服从图2由用户选择。
- `视频1`：当前片段的源动作视频，只负责动作、表演、发丝运动、镜头和剪辑。

若增加独立服装图，上传顺序变为 `图1人物、图2服装、图3场景`。若有多张人物身份图，它们先连续占用图1、图2……，后续分组顺延。不要为了维持固定编号留下空槽。

## 视频和音频编号

- `视频1` 始终是本次 H3 生成所对应的源动作/编辑片段。多段任务中，每次提交只更换视频1文件，图片顺序和编号保持一致。
- `视频2` 及以后只用于用户明确提供的独立辅助动作、运镜或时序参考；每段视频只能有一个主责。
- 视频1内嵌原音轨需要复用时标记为 `<视频1原音轨>`，不要求重复上传独立音频。
- `音频1` 及以后用于外部对白、音色、音乐或节拍参考；逐项写明是复制原信号还是只参考特征。

## 上传清单格式

确认前使用如下格式，以简短用途标签表示素材：

```text
本次上传顺序
视频1 → 第一段动作视频：动作、表情、视线、姿态、发丝运动、镜头、切点和原音轨。
图1 → 人物四视图：人物身份、五官、发型、体型和服装强约束。
图2 → 场景参考图：环境结构、材质、天气；光源职责等待用户选择。
```

不要在索引中复制附件的完整长文件名。存在多个同类素材时，用“人物正面参考、人物侧面参考、道具A、道具B、第一段动作视频、第二段动作视频”等短标签区分；文件路径只用于内部读取和实际上传，不进入提示词。

同时列出冲突规则：人物只服从人物图；独立服装图覆盖人物图中的服装；动作和镜头只服从视频1；环境只服从已确认的场景来源；光源只服从用户选定的来源；新道具只服从道具图。

## 提示词索引要求

每份提示词开头逐项定义 `<视频1｜简短用途>`、`<图1｜简短用途>`、`<图2｜简短用途>`、`<音频1｜简短用途>`。每项必须包含：锁定项、负责项、不得影响项；不得包含完整文件名或路径。后续时间轴与约束继续引用编号标签。多段提示词的图片/音频索引完全一致，只有视频1的简短段落标签和该段相对时间轴改变。

## 直接能力路由

只加载当前任务需要的能力，避免把所有工具都串联执行：

- 媒体元数据、切点、抽帧、转码和时长验证：优先直接使用 `ffprobe`、`ffmpeg` 和本 Skill 的 `scripts/segment_video.py`。Windows 先检查已存在的本地或捆绑 FFmpeg，不假设在 PATH。
- 本地图片检查：使用图像查看能力；允许在 `work` 中保存裁剪、放大、标注或联系表副本，不改源图。
- H3 当前能力、官方限制、提示词组织和机械校验：直接使用可用的 `minimax-h3-video-prompt` Skill，并只读取与当前模式有关的参考。
- 人物素材不完整且用户要求制作稳定角色资产时：直接使用可用的 `ai-character-assets` Skill；只有用户要求生成或编辑图片时才调用图像生成能力。
- 用户明确要求操作 MiniMax 桌面或网页界面时：调用可用的计算机/浏览器控制能力；提交生成、付费或外部账号操作仍遵守确认边界。
- 需要最新 H3 限制时：只查 MiniMax 官方 API 文档和官方模型仓库；不要用旧记忆替代当前核验。

不为已经能用本地工具完成的步骤安装插件；只有用户明确点名缺失插件、搜索已穷尽且插件确实可用时，才建议安装。
