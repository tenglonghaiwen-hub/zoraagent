# 前端设计系统

本仓库没有应用前端。用户面前端是 GitHub README、生成的位图资产与 SVG 支持资产。

## 设计目标

- 干净、电影感、高对比度呈现。
- 无折叠 Markdown。
- 无过载的霓虹文案。
- 在 GitHub 移动端与深色模式下可用。
- 清晰的从这里开始决策路径。
- 在技能地图上方可见的验证命令。

## 资产规则

- 使用 SVG 处理简单结构支持图。
- 当资产需要电影感纹理、真实场景深度或视觉叙事时，对 README 主角、操作系统信息图、技能地图信息图、能力图、CDN 分发图、参考角色图、制作交付图与 QC 栈使用生成的位图图像。
- 位图主角/信息图/地图资产应在 GitHub README 宽度下无 logo、无水印且可读。
- 当标签大、短、已修正且在图像旁边的可访问 Markdown 中重复时，允许文字密集信息图。
- SVG 资产必须包含 `<title>` 与 `<desc>`。
- SVG 资产中无外部脚本、图像、字体或追踪。
- 避免泛化镜头仪表板、密集装饰噪音与不可读的微小标签。
- 手动检查生成文字；拒绝乱码词、丑陋字体处理、低对比度、嘈杂装饰与占位符风格的面板。

## README 规则

- 行长不超过 500 字符。
- 表格应有真正的换行符。
- 每个主要部分应回答一个用户决策：它是什么，我从哪里开始，存在哪些技能，如何验证，什么变化。
- 位图主角艺术应避免水印与微小文字。文字密集信息图标签也必须在 Markdown 中表示以确保可访问性与搜索。

## 编辑设计令牌（v6 首屏）

首屏使用工作室规格表系统。将这些令牌应用于每个手工构建的矢量资产；永远不要重新引入渐变、发光块或多色调强调坡道。

| 令牌 | 深色 | 浅色 |
|---|---|---|
| 背景 | `#100E0A` 暖墨 | `#F7F3EA` 暖纸 |
| 前景 | `#EDE6D6` | `#1C1914` |
| 弱化 | `#9A917D` | `#6F6757` |
| 细线 | `#2E2A22` | `#D8D0BE` |
| 强调色（单一） | `#E2A75E` 琥珀 | `#A86F24` 琥珀 |

- 显示字体：`Didot, 'Bodoni MT', 'Hoefler Text', Baskerville, 'Palatino Linotype', Georgia, serif` —— 系统提供高对比编辑衬线时的字体；Georgia 作为通用回退；字重 400，无外部字体。标语以衬线斜体格言形式设置，句首小写，而非等宽。
- 脚本强调：`'Snell Roundhand', 'Apple Chancery', 'Gabriola', 'Segoe Script', 'Brush Script MT', cursive` —— 一条书法线，使用一次，用于 wordmark 的 `Skill OS` 一半，与雕刻的 Didot `Seedance 2.0` 配对。这是唯一的润色；其他一切保持纪律。仅系统脚本，无外部字体，优雅回退到 `cursive`。让 `Seedance 2.0`、标语与所有规范标签远离脚本，使报头保持清晰。
- 规范字体：`ui-monospace, 'SF Mono', SFMono-Regular, Menlo, Consolas, monospace` —— 字重 400，较小尺寸，宽字距（眉签 6-7px）；标签低语，wordmark 言说。
- 母题：链轮条、取景器角标记、十字准线、时码、波形刻度 —— 绘制为细线工作。
- 报头结构（1200x470）：眉签携带一条短琥珀色引导线在其左侧，一个带细发线的单一琥珀色菱形分隔 wordmark 与标语。给 wordmark 慷慨的垂直呼吸空间；画布高度的存在是为了让它呼吸，而非被填满。单一琥珀色强调（眉签引导线、`OS` 后的 `.`、菱形、REC 点）—— 永远不要第二种色调。
- 报头作为主题感知对（`hero-dark.svg`、`hero-light.svg`）在 `prefers-color-scheme` picture 元素后发布；运行图（`skill-map.svg`）携带其自己的背景，以便它在两种主题上都能阅读。
- 不要将版本号或计数烘焙进矢量资产；它们会过时。使用永恒标签（ROUTE / VERIFY / DIRECT / DELIVER）。
- 生成的位图艺术仅在画廊中。README 的工作界面是矢量。
