# 续拍交接

对每一次续拍、延长、下一镜头、衔接、修复尾部或重新锚定的请求，使用本参考。后继提示词必须基于已接受源画面或已接受尾帧。

## 源关卡

在以下内容已知前，不要撰写续拍提示词：

- 项目 ID 与当前片段 ID；
- 父级片段 ID；
- 已接受源片段或已接受尾帧；
- 观察到的结束状态；
- 已完成节拍；
- 保留的未来节拍；
- 连续性锁定；
- 精确参考注册表；
- 活跃平台或保守的平台档案。

若来源缺失，请求该片段、尾帧或精确的可见结尾描述。不要凭空发明。

## 交接记录

记录：

- 观察到的开始状态；
- 观察到的结束状态；
- 开放动作向量；
- 摄影机相位；
- 屏幕方向；
- 角色姿态与目光；
- 道具归属、位置与状态；
- 地点与持久环境；
- 灯光相位；
- 环境声、已完成对白、活跃对白、音乐相位与音效相位；
- 观察置信度与不确定性。

## 无缝 vs 下一镜头

仅当下一代从已接受画面延续同一镜头、同一地理与同一开放动作时，使用 `seamless_continuation`（无缝续拍）。

当编辑性剪辑适当时，使用 `intentional_next_shot`（有意下一镜头）。它可保留故事连续性，但不承诺精确的画面连续性。

当已知开始状态必须达到已知最终状态时，使用 `bridge_between_known_states`（已知状态间衔接）。

当父级片段最后数秒失败时，使用 `repair_tail`（修复尾部）。

当延长深度或可见漂移使链条不稳定时，使用 `reanchor_after_drift`（漂移后重新锚定）。

## 已完成与保留节拍

每条续拍提示词必须排除已完成节拍与保留的未来节拍。若 Clip 01 已经退出了终点，Clip 02 不得再次展示该终点退出。若车辆离场被保留到 Clip 03，Clip 02 必须在离场前停下。

## 精确参考标签

逐字节保留标签：`@Image1`、`@Image 1`、`[Image1]`、`[Video 1]` 与界面等价物不得被规范化、翻译、重新编号、改变大小写或重新格式化。

## 接受规则

已接受的观察状态覆盖计划状态。被拒绝的画面永远不能成为正典。未来提示词在先前的已接受镜头被审阅前保持临时。
