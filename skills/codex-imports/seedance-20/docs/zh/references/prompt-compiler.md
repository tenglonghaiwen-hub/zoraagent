# 提示词编译器

编译器将内部项目状态转化为针对当前片段的一条自然语言 Seedance 提示词。JSON 或 YAML 可用于组织规划，但发送给 Seedance 的最终提示词保持可读散文，除非用户明确要求结构化输出。

## 输入

- 项目状态；
- 当前片段契约；
- 平台提示词档案；
- 参考传递契约；
- 续拍的观察源状态；
- 已完成与保留节拍；
- 连续性锁定与允许的变更；
- 提示词预算。

## 编译顺序

1. 血统：在面向用户的契约或胶囊中命名 `project_id`、`clip_id` 与父级，若会浪费提示词预算则不必一定出现在最终提示词中。
2. 源角色：识别活跃参考标签及各自控制的内容。
3. 实际开场状态：对续拍使用观察到的画面，对首片段仅使用计划状态。
4. 当前片段动作：带端点的一个叙事职责。
5. 摄影机与动作相位：当连续性重要时包含继承的向量。
6. 灯光、环境、风格与音频：仅包含状态关键或情绪关键子句。
7. 排除项：已完成节拍与保留的未来节拍。
8. 端点：本片段必须达到的已完成状态。

## 自然语言提示词规则

不要向 Seedance 发送内部 JSON。不要包含所有未来片段。不要将计划的结局描述为已发生。不要重演已完成动作。不要执行保留的后续动作。不要发明确定性保证。

使用片段作用域语言：

- "Begin with..." 用于观察到的开场状态。
- "Continue the same..." 仅当存在源画面时使用。
- "This clip only..." 用于当前叙事职责。
- "Stop when..." 用于端点控制。
- "Do not yet..." 用于保留的未来节拍。

## 压缩

当提示词必须缩短时，按以下顺序保留：

1. 精确参考标签与角色边界。
2. 实际开场状态。
3. 当前动作与端点。
4. 连续性锁定。
5. 已完成节拍排除。
6. 保留节拍排除。
7. 摄影机或开放动作向量。
8. 音频相位。

首先删除泛化风格加成词、重复形容词、未来故事摘要、参考中可见的背景、次要动作与推测性的内部备注。
