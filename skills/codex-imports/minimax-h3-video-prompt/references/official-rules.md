# MiniMax H3 官方能力边界

更新时间：2026-08-05。以下内容来自 MiniMax H3 V2 API 文档和 MiniMaxAI 官方模型仓库，作为生成和校验的硬约束。模型与接口规则属于高频变化信息；涉及 API 提交、参数限制或当前日期晚于本文件更新时间时，先核对官方文档：

- https://platform.minimax.io/docs/api-reference/video-generation-v2-create
- https://huggingface.co/MiniMaxAI/MiniMax-H3

## 支持的工作方式

- 文生视频：只提供文字提示词。
- 首帧、尾帧或首尾帧图生视频：提供文字和 0—2 张首尾帧图片；不提供图片时等同文生视频。
- 多模态参考生成：使用图片、视频、音频的任意有效组合，控制人物、产品、动作、镜头、风格、声音或剪辑节奏。
- 视频编辑：通过参考视频与精准文字指令，修改人物、物体、场景、光影、声音和节奏；它属于多模态参考生成的应用方式。

首尾帧入口与多模态参考入口互斥：同一请求不能同时包含 `first_frame` / `last_frame` 与 `reference_image` / `reference_video` / `reference_audio`。

## 输出限制

| 项目 | 限制 |
|---|---|
| 模型名 | `MiniMax-H3` |
| 分辨率 | `768P` 或 `2K` |
| 时长 | 4—15 秒，只接受整数 |
| 画幅 | `adaptive`、`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` |
| Prompt | 不超过 7000 字符 |

旧资料中出现的 5—15 秒或 1440p 属于较早口径，不作为当前校验标准。

画幅还受模式约束：

- 文生视频必须使用一个明确画幅，不能使用 `adaptive`。
- 首帧、尾帧或首尾帧模式由输入图片决定画幅，接口按 `adaptive` 处理。
- 多模态参考模式可以使用 `adaptive` 或上述任一明确画幅。

## 输入限制

### 首尾帧入口

- 图片数量：0、1 或 2 张。
- 图片宽高：256—5760 像素。
- 宽高比：2:5—5:2。
- 支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF。

### 多模态参考入口

- 图片：最多 9 张，每张不超过 30 MB。
- 视频：最多 3 段，每段 2—15 秒，合计不超过 15 秒，每段不超过 50 MB。
- 音频：最多 3 段，每段 2—15 秒，合计不超过 15 秒，每段不超过 15 MB。
- 混合输入：所有图片、视频和音频合计不超过 12 个文件。
- 音频不能单独作为参考输入，必须同时提供至少一张图片或一段视频。
- 视频容器支持 MP4、MOV；视频编码支持 H.264/AVC、H.265/HEVC；视频内音频支持 AAC、MP3。
- 参考视频帧率必须在 23.976—60 FPS 范围内。
- 音频支持 WAV、MP3。
- 单次 API 请求体不超过 64 MB；大文件优先使用 URL。
- 图片和视频宽高范围均为 256—5760 像素，宽高比为 2:5—5:2。

## Prompt 与素材职责

- 图片可负责人物、产品、场景、风格、首帧或尾帧。
- 视频可负责动作、机位、运镜、剪辑节奏、表演和需要保留的原始内容。
- 音频可负责声音、音色、对白、音乐节拍和音效节奏。
- 多个参考素材必须在提示词中明确各自职责，避免身份、动作或风格互相污染。

## 官方能力重点

- 统一理解文字、图片、视频和音频。
- 参考并融合人物、动作、声音、情绪、镜头、风格和创作意图。
- 精准编辑人物、物体、场景、声音和节奏。
- 面向品牌影视、视觉包装、剧情、电商、数字体验、游戏、硬件工业、具身智能和风格化动画等生产场景。
- 支持多素材联合参考、角色/动作/镜头拆分参考，以及音色克隆和迁移。
- 支持角色与物体、场景与视觉效果、声音与台词的单点或组合修改。
- 对多项编辑要求使用原子指令，逐项复核高精度指令遵循。
