# 整套图片 Agent

图片专业子 Agent 负责共同风格与逐张内容规划，宿主负责参数校验、独立提交及结果归组。主 Agent 仍通过 `delegate_media_task` 委派，不直接提交媒体。

## 使用方式

在 Agent 对话中引用原图，说明需要一套几张图片及每张内容。例如：“以 @图片1 为产品参考，生成四张独立详情页：首页、领口、版型、面料，统一白背景、柔光、9:16、2K。”

仅要求方案时不生成；实际生成需要用户授权。修改代码和自动化测试不会代替用户发起付费生图。

## 结构化控制

- `preview_image_suite`：免费校验 `title`、`sharedStyle`、`items[{title,prompt}]` 及共同模型、比例、分辨率。当前整套支持 2–12 个独立页面；全部校验通过后才允许提交。
- `submit_image_suite`：每个页面使用“共同风格＋当前页面描述＋禁止整套拼图”的提示词，注入相同原始参考素材，固定 `count:1`、`concurrency:1`。不向上游发送合并的整套提示词。
- 同一描述的多个变体继续使用普通生成；不把单次超限数量自动拆为 4+1。
- 当前图片 Agent 内置该流程，无需用户手动选择技能。这是生成约束，不保证字体排版像素级一致，也不会自动把尚未生成的首页当作参考图。

## 展示与恢复

更换参考素材时，后端按素材内容地址计算指纹，区分替换、追加、编号变动与未变更；同名不同内容也触发提示词复核。主 Agent 和图片子 Agent 都接收变更摘要，重新分析本轮图片，更新各页以及共同风格中的旧主体描述，保留仍适用的布局与用户约束。旧会话没有指纹时也要求复核。该机制约束 Agent 规划，不是独立视觉审核，不能保证模型必然识别全部细节；不会自动付费重生成或覆盖旧结果。

沿用对话中的整组卡片：顶部一份共同风格与逐张说明，下方按计划顺序并列结果，共用全部插入画板、下载、加入参考、刷新等操作。每张显示标题和状态；详细信息包含独立提示词、任务编号及保存的真实请求体。

收据携带套图编号和页面位置，保存在会话的 `generationTasks` 中；客户端序列化保存全部子任务，逐个查询原始任务编号。某张尚未完成时保留空位，不拿其他图补位。旧收据不能覆盖更高版本的完成结果。

同一轮重复提交同一套结构复用原结果。提交失败或未知时停止后续页面，不自动补交或重试；缺少任务编号的页面标为“未提交”。云端已完成任务的恢复能力沿用媒体收据机制；生成请求到达上游而没有取得可恢复结果时仍可能处于未知状态，不能保证自动找回。

整套“重新编辑／重新规划整套”返回 Agent 规划输入框，不把合并说明重新发送为普通 `n>1` 请求；用户需核对参考素材并确认后再生成。

## 验证

`tests/image-suite.test.mjs` 使用模拟上游验证提示词隔离、原图共享、数量1、重复提交防护、失败停止、乱序完成归位、会话序列化恢复与查询不提交。未用真实付费生成验证画面质量。
