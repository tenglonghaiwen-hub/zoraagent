# 产品内子 Agent 实施记录

> 维护说明（2026-09-15）：当前能力、入口与限制见 [当前实现状态](CURRENT-STATUS.md)。本文中的版本验收数字、当时状态和后续计划保留为历史记录；涉及 RunningHub 的接入计划已取消，相关接口现已移除。

2026-09-14。本轮实现主 Agent、图片子 Agent、视频子 Agent，属于产品运行时能力。

- 主 Agent 通过 delegate_media_task 分派，专业子 Agent 使用独立模型调用。继承用户选定的文字模型；未指定时沿用后端默认配置。
- 专业子 Agent 使用宿主设置的独立角色说明，仅开放目录、预览、提交三个工具；代码限制媒体类型并禁止递归和原始 API 旁路。
- 图片默认 gpt-image-2，视频默认 MiniMax-H3；合法用户明确要求通过上下文交给子模型。明确参数的语义识别仍依赖模型，不宣称任意自然语言约束均被程序化验证。
- 每用户轮最多 4 次顺序委派，每子 Agent 最多 2 轮工具调用；普通问答无需子调用。
- 同轮子 Agent 共用生成 runner、去重状态及 generationTasks 收集器。素材由宿主传递；子总结失败仍保留真实收据，供现有 UI 查询恢复。

## 验证

全量 53 项单元测试通过，修改源码语法检查通过。新增测试覆盖独立主→子调用、原图传递、继承文字模型、默认 H3、媒体类型限制、主直接生成拒绝、禁止递归、顺序与次数限制、子失败后保留收据以及重复委派只提交一次。

测试均使用模拟模型与本地假接口，没有实际付费生成，没有重启用户服务。前端契约未改变，继续使用 studio144 的 generationTasks 消息回显。

## 边界

- 当前针对 Responses / Chat Completions 工具后端；CLI 后端未接通这套 JS 工具委派，不属于本轮验证范围。
- 尚无通用异步 DAG：待生成图片不会自动等待完成后传入视频任务，不实现跨轮自动链式续跑。
- 策划、剪辑、验收子 Agent 尚未新增；现有 OpenMontage 工具仍由主 Agent 使用。
- 同轮参数去重不等于跨聊天请求幂等；模型调用增加会带来额外文本费用，实际供应商费用未测。
- 重启后端才能加载本轮代码；无收据的旧任务不能凭本轮改动恢复。
