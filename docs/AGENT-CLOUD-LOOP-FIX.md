# 云端登录与本地 Agent 执行修复

2026-09-19。

原问题：默认云模式将 `/api/chat` 发往 Worker 的单轮 Chat Completions 代理。该代理没有 Codex 工具循环，也不处理客户端传入的技能和参考素材；通用回复过滤还会替换正常技术回答。

修复后的桌面请求链路：客户端 authFetch → 同源 `/api/agent/chat` → 固定官方网关验证用户 → 包内 Codex → 云端 `/api/agent/v1/responses` → 服务端配置的供应商。Responses 输入、工具和 SSE 原样转发，工具执行留在本机。用户登录 JWT 仅在运行内存中传递给 Codex，供应商密钥仍由云端配置提供。

云用户的会话与 Codex home 使用用户 ID 哈希分目录；切换登录身份时，活动任务阻止内核切换。旧云端会话 ID 没有本地记录时创建本地新线程，主对话传入最多十轮可见文字作为迁移上下文。未保存的历史素材和旧云端执行轨迹无法重建。

生成工具通过登录后的云端生成接口提交，返回回执后不重复提交；预览和本地工具仍走本机接口。此改动不宣称修复云端媒体任务的全部持久化、幂等或供应商查询差异。

网关按现有定价方法对每次成功接受的模型请求收费；一个 Agent 任务可产生多次模型请求。没有执行付费验收。当前流开始时扣费，流中断后的退款与生产级并发预占仍需独立完善，不能称为完整计费闭环。

保留对直接身份问题的标准回复，但普通技术回答不因提到供应商名称而被整段替换。回环地址加入 Codex 进程 NO_PROXY，避免系统代理将本地模型测试请求返回 503；公网模型请求的代理设置不因此改变。

部署需要同步更新 Worker 和本地后台/客户端。仅更新 Worker 不会自动在用户电脑启动 Codex。实际付费模型与媒体生成未经本次测试确认；真实包内 Codex 使用本地模拟模型已验证工具调用、连续对话及重启恢复。
