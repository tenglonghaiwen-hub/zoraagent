# 音频转写与时序画面接入

> 维护说明（2026-09-15）：当前能力、入口与限制见 [当前实现状态](CURRENT-STATUS.md)。本文中的版本验收数字、当时状态和后续计划保留为历史记录；涉及 RunningHub 的接入计划已取消，相关接口现已移除。

## 已实现

- FFmpeg 对已上传视频按每秒 2 帧采样，覆盖全时段，生成带时间标签的时序拼图，供主 Agent 和媒体子 Agent 分析动作起点、过程、结束与镜头变化。
- 提取 16kHz 单声道 WAV，调用多元探索 `/v1/audio/transcriptions`，默认 `whisper-1`、multipart 上传、`verbose_json`。使用服务端 `DUOYUANX_API_KEY` 与 `DUOYUANX_BASE_URL`；模型可由 `ZORA_TRANSCRIPTION_MODEL` 覆盖。
- 转写服务返回合法时间段时保留；未返回时明确无台词时间戳。语音转写不等于音乐、音效分析。
- 转写失败时继续画面分析并向模型传入明确错误；不自动重试上游。成功转写按内容、模型、服务和凭据在进程内缓存，重启后缓存不保留。

## 范围

原视频不修改。仍限 MP4/MOV/WebM/AVI data URL、单文件 30 MiB。参考视频合计不超过 120 秒或 240 帧，超限明确拒绝，不静默截断。图片与拼图合计最多 6 个视觉输入，每个视频最多 3 张拼图。

这是全时段定间隔采样，不是逐帧、像素级运动跟踪；快速动作与细节可能遗漏。不能宣称完整连续动作理解。音频接口已按文档实现，未用用户密钥进行付费验证；真实账户模型权限仍待验证。

## 验证

全量 79 项测试通过，随后新增两项转写时序/聊天失败回归，相关 6 项测试全部通过。真实 FFmpeg 测试包含时序拼图、音轨参数、原素材保护与超限拒绝；转写 HTTP 使用模拟响应。

重启后端加载改动，再重新上传视频发送。运行时转写可能产生供应商费用；本轮开发没有实际付费调用。临时文件仍保留在系统 Temp 的 zora-video-frames-* 目录，未清理用户文件。
