# 后端部署准备

> 维护说明（2026-09-15）：当前能力、入口与限制见 [当前实现状态](CURRENT-STATUS.md)。本文中的版本验收数字、当时状态和后续计划保留为历史记录；涉及 RunningHub 的接入计划已取消，相关接口现已移除。

本轮仅增加只读检查工具和部署交接说明，没有执行远程部署、重启现有服务、读取密钥或提交生成任务。桌面安装包由构建角色负责；部署角色负责后端运行、健康检查、持久化、备份与回滚。

## 当前状态与上线边界

- 当前是本地开发骨架，根 `package.json` 使用 `node apps/server/server.mjs` 启动，默认端口 8787。
- 当前 API 没有统一的用户鉴权及任务归属校验，不能直接暴露公网。`server.listen(PORT)` 未显式绑定回环地址；本地使用应限制网络访问，不能把启动日志中的 127.0.0.1 当成监听范围保证。
- 尚未指定远程服务器、域名、运行账号和发布方式。本轮不新增 Docker 或假定某个云平台已经可用。
- 后续上线前需完成鉴权、任务访问控制、TLS、网络访问限制、请求限额、日志脱敏和运行权限设计。第三方密钥只注入远程后端，不进入桌面安装包、客户端配置或日志。

## 只读能力检查

在项目根目录运行：

```powershell
& .\runtime\node-v24.21.0-win-x64\node.exe .\scripts\check-deployment-readiness.mjs
```

默认仅 GET `http://127.0.0.1:8787/api/generation-capabilities`，期望 `durableTasks:true`、`agentTasksVersion:1`。退出码 0 表示此能力契约匹配；非 0 表示旧版、不兼容、无法访问或响应错误。可显式传入已授权目标的基础 URL；工具拒绝 URL 内嵌账号密码、查询参数和重定向，不读取 `.env`，不调用生成或任务查询接口。

此结果不证明供应商可用、余额充足、磁盘可写、任务恢复成功或服务具备生产安全条件。该端点目前只是静态能力声明，不是完整就绪检查。

## 持久化与运行

`apps/server/server.mjs` 默认将生成任务写入项目 `data/generation-tasks`。远程部署必须通过 `ZORA_TASK_STORE_DIR` 指定发布目录之外的固定绝对路径，由服务账号独占写入；权限、容量、备份及保留期限需要明确。发布新代码或清理旧版本时不能删除该目录。

当前文件任务存储按单实例运行设计，未经协调设计不要让多个后端进程共用一个任务目录。任务 JSON 持久化不等于全部会话、桌面附件或上游素材永久保存；这些数据需要分别安排保存与恢复策略。

服务管理应明确启动命令、工作目录、端口、自动重启和日志轮转。环境变量配置记录只保存变量名与用途，不把密钥写入交接报告。

## 发布、备份与回滚

1. 发布前记录当前版本文件哈希、运行配置的非敏感部分与能力检查结果。保留上一版代码。
2. 停止接收新任务；核对正在提交及轮询的任务。优先等待提交阶段完成后，在停写状态或一致性快照机制下备份独立任务目录，避免复制时任务状态变化。
3. 以隔离数据执行本地模拟恢复测试，再切换版本并进行能力检查。验证已有任务恢复时只查询已知任务 ID，不重新提交生成请求。
4. 若回滚，先停止新版，再确认旧版兼容当前任务格式；让旧代码使用保留的最新任务目录。不能直接用过期备份覆盖当前目录，否则可能丢失已提交回执并产生重复提交风险。
5. 数据损坏时先保留现场副本，逐项核对任务 ID 和上游记录，再制定恢复操作。删除、覆盖恢复或真实生成重试须遵守用户确认边界。

## 本轮验收

能力脚本以本地 mock 验证新版契约通过、缺少 `agentTasksVersion` 的旧版拒绝。实际远程上线、真实付费生成、生产备份恢复和公网安全验收均未执行。
