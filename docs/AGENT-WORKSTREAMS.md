# Zora 子智能体分工

> 维护说明（2026-09-15）：当前能力、入口与限制见 [当前实现状态](CURRENT-STATUS.md)。本文中的版本验收数字、当时状态和后续计划保留为历史记录；涉及 RunningHub 的接入计划已取消，相关接口现已移除。

本轮按用户要求分为 UI、测试、源代码、架构、构建、部署六个工作流，由主智能体统一协调。首轮是只读审计与本地模拟测试；发现问题不等于已经修复。子智能体是当前任务内的协作角色，不是无人值守的后台服务。

## 协调规则

- 主智能体负责排序、整合、验收和向用户报告，不把“代码检查通过”描述成“真实生成成功”。
- app.js 是共享高冲突文件。修改前指定唯一负责人；UI 和业务修改分批合入。架构先给契约，源代码实现，测试验收，构建确认能启动。
- 修改前备份源码并记录哈希；前端修改同步更新两处缓存戳。保留用户数据及原交接文件，不自动初始化 Git。
- 默认使用模拟响应和隔离测试数据。付款、注册、外发消息、账号权限变更、批量删除按用户要求确认；不读取或复制密钥，不自行调用付费生成。
- 各角色输出：问题、证据、影响、负责文件、验证方式、尚未验证事项。
- 完成标准：失败原因可见、原图可追踪、已有任务只查询不重提、结果按任务对应、重启恢复通过模拟验证、桌面加载到正确服务版本。

## 首轮优先顺序

1. 提交、素材、结果回显和跨重启恢复闭环。
2. 服务版本与桌面启动流程，避免新前端连接旧后端。
3. 会话阅读位置、画布菜单及主题等 UI 回归。
4. 拆分共享大文件，再制定 Electron 分发方案。

具体审计发现以各角色核查结果为准；本文件定义职责，不宣称以上工作已完成。

## 2026-09-14 首轮证据与任务分配

- 测试：14 个单元测试文件共 33 项通过、0 失败；使用 bundled Node 与 mock / 本地假网关。31 项桌面场景及专项脚本本轮未执行。
- 源码 P1：Agent submit_generation 没有 requestId，绕过 server.mjs 的持久任务分支；统一为任务收据后才能可靠恢复。
- 源码 + UI P1：Agent toolTrace 的待完成任务没有进入媒体后台轮询；需关联正确的会话、消息和结果，不能只提取完成 URL。
- 源码 + UI P1：Agent 上传逻辑仅对不超过 4 MB 的图片携带内容，视频、音频及读取失败可能只留下元信息；统一素材解析并明确提示。
- UI P2：画布 Agent renderLog 仍每次滚到底部；主会话的定位修复未覆盖画布。
- UI P2：画布 Agent 未保留和渲染 toolTrace，生成结果回显需接统一任务契约。
- 部署：尚未明确远程部署目标，首轮未发现 Docker、进程守护或反向代理配置；先交付可执行部署方案，不直接上线。
- 部署：任务账本默认在项目 data/generation-tasks；发布前须通过 ZORA_TASK_STORE_DIR 设定独立持久目录，并验证备份与回滚不丢任务。
- 构建：目前只有源码启动，没有 Electron 打包命令和产物配置；先建立可复现构建与本地产物验收。
- 构建 + 架构：Electron 通过端口与 /api/models 检查就复用后端，未校验服务版本；须设计版本兼容协议，避免窗口重开仍连旧进程。
- 架构决定建议：所有生成入口采用稳定请求 ID 与同一持久任务服务；素材 ID、输入内容、任务 ID 和输出建立关联，只有工具返回有效输出才标记完成。

这些是首轮代码审计结果，尚未在本轮实施修复；真实供应商生成未测试。
