# 产品内图片与视频子 Agent 最小契约

> 维护说明（2026-09-15）：当前能力、入口与限制见 [当前实现状态](CURRENT-STATUS.md)。本文中的版本验收数字、当时状态和后续计划保留为历史记录；涉及 RunningHub 的接入计划已取消，相关接口现已移除。

日期：2026-09-14。本文描述 Zora 产品运行时的主 Agent、图片子 Agent、视频子 Agent，区别于开发团队的 UI、测试、源码等分工。本文是实施接口约定，不是实际付费验证或完整工作流引擎的验收声明。

## 主 Agent 委派接口

主 Agent 新增工具 `delegate_media_task`，参数如下：

```json
{"kind":"image","task":"依据用户提供的参考图，给人物添加黑色墨镜，保持其余内容不变"}
```

- `kind` 必填，只允许 `image` 或 `video`；`task` 必填，为非空任务指令，最多 8000 字符。
- 主 Agent 负责理解用户目标、拆分与说明；子 Agent 负责指定媒体类型的参数选择、预览校验与生成提交。
- 实际生成权限仍继承用户原始指令；仅要求方案、分析或预览不能因为发生委派而自动提交生成。
- 本版顺序委派，同一主 Agent 用户轮次最多执行 4 次子调用。次数在执行前由宿主检查，不依赖提示词；超出返回明确错误。

## 子 Agent 运行边界

- 子 Agent 继承当前主会话选择的文字模型 `input.modelId`；未显式选择时沿用同一后端默认解析。图片/视频模型不是子 Agent 的推理模型。
- 每次子调用 `maxRounds: 2`，即最多两轮可调用工具的模型响应及随后一次禁工具最终响应。子 Agent 不暴露 `delegate_media_task`，不允许递归委派。
- 工具只允许 `list_media_models`、`preview_task`、`submit_generation`，宿主同时执行名称白名单校验，不能仅从 schema 隐藏。禁止 `call_api`、OM、RunningHub、文件系统、直接供应商生成代理等旁路。
- 目录、预览和提交限于委派的媒体类型。图片子 Agent 不能提交视频，视频子 Agent 不能提交图片；类型冲突在任何生成请求前拒绝。
- 图片默认 `gpt-image-2`，视频默认 `MiniMax-H3`。用户明确指定的有效模型和参数优先，其余参数依据素材和任务决定并经过模型目录校验。不支持的明确要求应说明冲突，不擅自替换。

## 素材与上下文

主 Agent 的任务文字不能替代原始素材。宿主直接向子 Agent 传递当前请求已解析的 `references` 及可用于视觉理解的 `imageInputs`；素材不得由模型复制 Base64 到工具参数或文字历史。

子上下文包含用户原始指令、必要对话约束和当前委派任务，保留用户明确的模型/参数与不生成限制。生成 runner 使用相同可读素材引用；缺少原图时错误必须明确，不能静默改成文生图。

本版不实现任意节点 DAG 或异步依赖调度。前一步图片仍在生成中时，不能把任务 ID、虚构地址或说明文字当作视频参考图提交；应告诉用户等待图片完成。完成后的真实结果如需成为后续输入，必须通过宿主明确解析成新的素材引用，不能默认所有委派已自动串联。

## 共享任务与错误返回

继续使用 [统一任务契约](./UNIFIED-TASK-CONTRACT.md) 的 `generationTasks: [{task,draft}]`、稳定 requestId 和 `/api/generation-tasks/{id}` 查询路径，不创建第二套子 Agent 任务账本。

所有主/子提交通过同一宿主生成 runner，共享同轮提交去重状态及 generationTasks 收集器。模型重复调用或子 Agent 总结失败不得产生新的付费 POST。返回结果中的生成任务只来自真实收据或已有 submissionUnknown 占位记录。

委派结果最小结构：

```json
{
  "ok":true,
  "kind":"image",
  "reply":"图片任务已提交，等待生成结果",
  "generationTasks":[{"task":{"id":"stable-request-id","status":"running"},"draft":{"modelId":"gpt-image-2"}}]
}
```

上例仅省略展示字段；实际 task/draft 保持统一契约原结构。子模型失败时返回 `ok:false`、`error`，并保留本次已经取得的 generationTasks。收据同步写入主轮共享收集器，不能依赖子 Agent 最终回复解析才能收回。已完成任务、运行中任务、提交结果未知必须分别描述，不能因自然语言称成功而改变状态。

## 最小本地验收

1. 委派继承正确文字模型及宿主原图；默认媒体模型与用户显式要求正确传递。
2. 子工具白名单、kind 边界、4 次限制、maxRounds 2 与禁止递归均由代码保证。
3. 子调用的真实收据进入主响应；工具重试仅一次生成 POST，子回复失败仍有原收据。
4. 主/UI 继续用现有 GET 轮询和重启恢复；运行中的图像不会被当作视频素材提交。

验收使用模拟模型和模拟生成接口，不在本轮自动发起真实付费测试。
